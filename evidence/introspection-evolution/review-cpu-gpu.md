# Reusable CPU/GPU session review

No outstanding blocker was found in the declared reusable-session scope. This review changed no production files. Actual GPU execution and timing are performed separately by the parent task; the review's GPU fault tests use an explicit fake driver.

CPU: one owning JIT lifetime encloses all calls and close. Native threads join before result collection and before executable-code release. Every lane/call still allocates its own runtime Context. Independent probes in normal and optimized Python inject a result-collection failure and observe exactly one native Batch free, then verify that later calls recover. An unowned cached entry address is rejected before native invocation. A warmed owner moves to another host thread with exact outputs. Existing tests cover source/IR mutations, all selected fuel/depth outcomes, output failure recovery, repeated close and concurrent close.

GPU: an RLock serializes calls and close. A session context is created or pushed for each call and popped afterwards; idle ownership is detached, permitting later calls from another host thread. This agrees with the [NVIDIA context-management contract](https://docs.nvidia.com/cuda/cuda-driver-api/cuda_driver_api/group__CUDA__CTX.html): creation supersedes the caller's current context, and pop can restore it; explicit context destruction owns remaining allocations and modules. Failed context restoration marks the session unusable. Cleanup attempts all known resources, preserves the primary error with cleanup notes and retains failed-destruction handles for explicit retry. Successful clean discard permits a later fresh context after a device-call failure.

Eight focused GPU lifetime tests pass. Eleven independent fault probes pass in both Python modes: device selection, context creation, module loading, function lookup, allocation, input transfer, launch, synchronization, output transfer, context pop, and old-buffer freeing during growth. No failure publishes a numerical success. Owned resources and caller context are restored in the modeled failures; the growth test includes the newly allocated replacement and verifies a later fresh run. These probes are lifecycle evidence, not GPU arithmetic or hardware evidence.

Source text and implementation digests are checked each call; generated-code hash and compiled metadata bind cache entries. Exact row snapshots and int64 bounds precede device use. Source/result bindings are copied or reconstructed per report, so returned metadata does not alter cache state. Empty inputs remain NO_WORK. CPU exact GMP and GPU checked int64 domains remain distinct.

Source hashes are in review-cpu-gpu-bindings.json. Reproducible review_cpu_probes.py and review_gpu_probes.py and normal/optimized result files accompany this report. Existing-engine trace completeness and benchmark integration are reviewed separately; they are not established by session lifecycle tests.
