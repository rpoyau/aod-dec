# Active anchor formation-identity migration

The repaired producer exposed a real alias in the authenticated historical population constructor. In archived `baseline/input/population.py`, line 105 creates Monon formation components using occurrence number `j` at cuts `3*j`. Lines 109–113 reuse occurrence numbers 0 and 1 for higher-motif target returns starting at cut 30 and later. Since `trace` derives event names from lineage and occurrence, distinct formation and target events receive identical scoped event keys with different coordinates. The new joint motif guard correctly rejects them.

The active anchor adapter now applies the explicit rule `aod.anchor.formation-event-namespace.v1` before the first target motif is admitted. Every formation-component event name receives the prefix `active-anchor:formation:`. Its reflection witness's turnaround, outbound, return and target-start references receive the same one-to-one translation. The component is recertified and the construction's component-return references are rebuilt. Scope, scale, lineage, ancestor, geometry, native cuts, roles, reflection commitments and all target traces remain unchanged.

This is construction-time disambiguation of different occurrences, not relabelling an already admitted joint history. The original certificate is checked before translating the component. The adapter records the original→active event map and both return, trace and certificate digests. The active engine payload retains those bindings per node. Active input provenance declares the migration. No probability, pressure, scheduling, population, contact, gain, target or unit rule is changed.

Only the active `aod_m3_anchor.py` adapter and its owned tests are modified. The authenticated archive and its historical source/decoder/audit remain byte-identical; `original_replay` still launches the unmodified historical audit in a separate process. The active decoder does not silently migrate a stored historical wave: a new regression requires its conflicting collection to be rejected, while a freshly migrated active wave must decode and admit exactly.

Original active scripts, generated cases/inputs/report and initial normal/-O integration failures are preserved under `original-active/`, `original-active-bindings.json` and `initial-upstream-*.log`. Regenerated active records are new candidate evidence; they are not substituted into the historical archive.
