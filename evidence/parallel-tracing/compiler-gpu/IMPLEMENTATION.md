# Generated Dec GPU target implementation

`native/gpu_compiler.py` lowers the selected verified Dec branch into CUDA device statements and a typed row kernel. NVRTC emits PTX; the CUDA Driver loads and executes that actual generated artifact. Returned device values/status/source lines/fuel are consumed directly. There is no interpreter execution or CPU arithmetic fallback in this path.

Public API: `run_gpu_batch(program, function, rows, fuel=100000, max_depth=128, opt=0, param_types=None)`. `lower_cuda` returns generated source plus exact frontend/entry/implementation bindings; `compile_cuda` returns PTX plus its digest and actual compiler options. Bounded shared source/input admission comes from `native.batch`.

The selected entry supports pure nonrecursive `int`/`bool`, assignment, assertion, return, checked integer `+`, `-`, `*`, unary operators, comparisons, Boolean short-circuit and conditionals. Every executed function/statement/expression tick follows the reference/native ordering. Argument types remain exact: Boolean is not admitted as integer. Parameters and dynamic intermediates must fit signed int64. Domain overflow is a distinct per-row `failure_kind=target-domain`, with no wrapped numeric claim. The standard spelling `-9223372036854775808` is encoded safely while retaining its original two expression ticks; bare positive 2**63 is rejected. General ratios, strings, arbitrary-precision arithmetic, call trees, effects, native witness admission and field formation are outside this target.

Rows preserve source input order and expose result/stdout/error/error_line/exit_code plus failure_kind and remaining_fuel. Source execution failures carry the original assertion or fuel/depth reason. Fuel/depth exhaustion has line zero as in the existing native runtime; assertions and target arithmetic overflow carry their source statement line. Every row has independent context.

Source text, canonical verified IR, selected entry, generated CUDA, compiled PTX, input rows/limits, result records, compiler/adapter files, NVRTC version, actual options and device/driver identities are bound in the result. Report timing includes source/input validation, lowering, NVRTC, context/module/allocations, copies, launch/synchronization, cleanup and materialization. No speedup has been claimed.

NVRTC has an optimization switch rather than LLVM's three optimizing levels: request O0 emits with `--device-debug`; O1/O2/O3 use `--dopt=on`. Both the requested level and actual options are retained. Offline NVRTC compilation succeeded for O0 and O3 on the generated incidence source; compilation itself is not device execution.

Focused local tests pass normally and under -O: 12 tests, with one class-level device-unavailable skip covering three hardware tests. Tests include independent signed-incidence truth tables; changing source arithmetic changes generated code/output; generated C++ execution with `-ftrapv`; 2,343 independent exact arithmetic endpoint/random cases; every executed-path fuel threshold 0..39; depth-before-body failure; assertions; short-circuit/conditional avoidance of overflow; strict input/domain/grammar rejection; source/artifact drift rejection; malformed result rejection; no-device no-fallback; and explicit no-work nonexecution. The parent actual-host normal run now passes all 15 tests with no skips; its retained log is `parallel-tracing/gpu-compiler-device-normal.log`. The optimized actual-device run and full retained-boundary hardware driver remain separately owned by the parent task. No timing speedup follows from these correctness checks.

The independent review is separate from this implementation note. Exact current source hashes are in `SOURCE_BINDINGS.json`.
